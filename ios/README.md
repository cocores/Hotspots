# Hotspots (iOS)

A native SwiftUI port of the `index.html` Hotspot Builder — upload an
image, tap to drop numbered pins, attach a title/description/media/link to
each one, then browse it in Preview mode. Unlike the web tool (which keeps
everything in browser memory until you export a file), this app saves
projects to Firebase so they sync across launches and devices signed in
with the same anonymous identity.

**I (the assistant) cannot compile, run, or test Swift/Xcode in this
environment** — there's no macOS toolchain available here. Everything
below was written carefully against the Firebase iOS SDK's documented
APIs, but you'll be the first to actually build it. Treat the first build
as a real "does this compile" pass, and tell me any errors — I can keep
fixing from error output even though I can't reproduce them myself.

## What's different from the web tool

- **Cloud-backed projects, not export.** Every project (image + pins) is
  saved to Firestore/Storage under an anonymous per-device identity
  (Firebase Anonymous Auth) instead of living only in memory until you
  export an HTML/embed/WebP file. There's no export feature in this v1 —
  the point is a real saved project you can reopen, not a one-shot output
  file. Say the word if you want export added back.
- **"Link" instead of a B&H product ID.** The web tool's B&H-specific
  field (`bhId` → a hardcoded `bhphotovideo.com` product URL) became a
  plain optional URL field, since baking in one retailer's link format
  didn't make sense to carry over as-is.
- **Ownership-gated, not open.** The web tool has no accounts at all;
  everything typed into it just lives in that tab. Here, Firestore
  Security Rules (`../firestore.rules`) restrict a project's writes to the
  anonymous `uid` that created it (`request.auth.uid`), since projects are
  now shared, durable cloud state instead of throwaway tab state.

## Structure

```
ios/
├── project.yml                 XcodeGen spec — generates the .xcodeproj
└── Hotspots/
    ├── HotspotsApp.swift         @main — FirebaseApp.configure()
    ├── Info.plist                 generated by XcodeGen, not hand-written
    ├── GoogleService-Info.plist    you provide this (gitignored)
    ├── Models/
    │   ├── HotspotProject.swift    Firestore document shape
    │   ├── Hotspot.swift            x/y are percentages, like the web tool
    │   ├── HotspotMedia.swift
    │   └── HotspotStyle.swift       color/animation/speed + hex Color helpers
    ├── Services/
    │   ├── AuthService.swift        anonymous sign-in, tracks the uid
    │   └── ProjectStore.swift       Firestore listener + Storage uploads
    ├── Views/
    │   ├── RootView.swift
    │   ├── ProjectListView.swift    project list, create-new flow
    │   ├── EditorView.swift          per-project screen: mode, save, sheets
    │   ├── EditorCanvasView.swift    image canvas, tap-to-place, drag-to-move
    │   ├── HotspotFormView.swift     add/edit sheet incl. media upload
    │   ├── HotspotListSheet.swift    hotspot list + stats, mirrors the side panel
    │   └── StylePanelView.swift      color/animation/speed picker
    └── Components/
        ├── HotspotPinView.swift      animated pin (pulse/ripple/bounce)
        └── HotspotTooltipView.swift  tap-to-reveal card in Preview mode
```

## One-time setup

### 1. Install XcodeGen

```bash
brew install xcodegen
```

### 2. Register an iOS app in Firebase

Reuse the same Firebase project as any other client, or create a new one,
at [console.firebase.google.com](https://console.firebase.google.com/):

1. **Project settings → General → Your apps → Add app → iOS.**
2. Bundle ID: `com.cocores.hotspots` (matches `project.yml`; change both
   together if you want a different one).
3. Download the generated **`GoogleService-Info.plist`** and place it at
   `ios/Hotspots/GoogleService-Info.plist`. It's gitignored on purpose —
   it's tied to your Firebase project, not something to commit.
4. **Build → Authentication → Sign-in method → enable Anonymous.** The app
   signs every device in anonymously on launch; without this enabled,
   every read/write will fail auth.
5. **Build → Firestore Database → Create database** (production mode —
   `firestore.rules` supplies the real rules regardless).
6. **Build → Storage → Get started** (production mode, same reasoning).

### 3. Deploy the security rules

From the **repo root** (not `ios/`):

```bash
npx firebase-tools login   # once
npx firebase-tools deploy --project YOUR_PROJECT_ID --only firestore:rules,firestore:indexes,storage
```

Without this, Firestore/Storage's default rules deny everything and every
save will fail even with valid config.

### 4. Generate and open the Xcode project

```bash
cd ios
xcodegen generate
open Hotspots.xcodeproj
```

Re-run `xcodegen generate` any time `project.yml` changes (new source
files are picked up automatically since it globs the `Hotspots/` folder —
you only need to regenerate after editing `project.yml` itself, e.g. to
bump the deployment target or add a dependency).

Build target: **Hotspots**, iOS 17.0+. First build will resolve the
Firebase Swift Package (`firebase-ios-sdk`) via SPM, which takes a few
minutes.

### 5. Run it

Simulator or a real device both work (Firestore/Storage don't need a real
device). Sign-in, project list, and saves all require network access.
